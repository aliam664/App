# استفاده و نگهداری UHM — راهنمای ساده

## شروع در پنج قدم

1. از [release مخصوص پایلوت](https://github.com/aliam664/App/releases/tag/uhm-platform-v0.1.0-pilot.1) فایل **UHM-Launcher-0.1.0-x64-setup.exe** را بگیرید. نسخه قدیمی v1.0.0 برنامه جدید نیست.
2. فایل unsigned است و هشدار ناشر ناشناس ویندوز ممکن است نمایش داده شود. پیش از نصب، SHA-256 را با فایل همان release مقایسه کنید. این هش جای امضای ناشر را نمی‌گیرد.
3. برنامه را روی **کامپیوتر اصلی خودتان** اجرا کنید. کد خصوصی تحویلی در `UHM-owner-access.txt` را در «فعال‌سازی لایسنس» وارد کنید. برنامه آنلاین باشد.
4. پس از اولین فعال‌سازی، پنل مدیریت با نقش **Owner** باز می‌شود. کد اولیه VIP است، تمام ۱۷ مجوز دارد و ۳۶۵۰ روز اعتبار آن از اولین فعال‌سازی شروع می‌شود؛ دائمی معرفی نمی‌شود.
5. در تنظیمات لانچر پوشه واقعی بازی را انتخاب کنید. در پنل، بسته واقعی با فایل‌ها، لینک مستقیم HTTPS، اندازه، SHA-256، مقصد و مراحل نصب بسازید و منتشر کنید. در دیتابیس عملیاتی هیچ مود نمونه‌ای به‌جای فایل واقعی منتشر نشده است.

**کد مالک را برای امتحان اول در سایت وارد نکنید، اگر قرار است در Windows استفاده شود.** کلید WebCrypto مرورگر و کلید محافظت‌شده Windows دو هویت متفاوت‌اند، حتی روی یک کامپیوتر. همان کد در برنامه به هر دو بخش لانچر و پنل دسترسی می‌دهد؛ برای استفاده هم‌زمان از مرورگر مستقل، یک لایسنس مدیریتی جدا صادر کنید. تب/مرورگر خصوصی و پاک‌کردن داده‌ها ممکن است هویت مرورگر را از دست بدهد.

## سایت واقعی و تمرین محلی

[سایت](https://aliam664.github.io/App/) و [پنل](https://aliam664.github.io/App/#/admin) اکنون build متصل به API هستند؛ ورود نمایشی عمومی ندارند. Redirect ممکن است آدرس را به `pages-preview/` ببرد؛ نام پوشه تاریخی است، mode در build-info برابر `connected-production` است. موتور نصب بازی فقط در Windows اجرا می‌شود.

برای تمرین امن با داده جعلی از `npm run dev` یا buildهای `build:pages` / `build:branch` استفاده کنید. اینها به‌عمد sandbox هستند. کد آزمایشی آنها در سرویس واقعی معتبر نیست. workflow ابتدا این sandbox را تست می‌کند، سپس برای سایت buildهای `build:live-pages` / `build:live-branch` را منتشر می‌کند. سورس UI یکسان است.

## کارهای روزمره از پنل، بدون ساخت مجدد برنامه

- صدور، نام‌گذاری، توضیحات، سطح، اعتبار، تعلیق، ابطال و آزادسازی دستگاه مشتری؛
- در «تیم»، اختصاص نقش و مجوزهای لازم به لایسنس همکار؛ هر نفر کد خودش را فعال کند؛
- افزودن/ویرایش بسته، لینک و مقصد، فایل‌های چندگانه، رمز آرشیو، وابستگی و انتشار **شماره نسخه جدید**؛
- بررسی تاریخچه، خطاها، نمودار و وضعیت سرویس.

تغییر نسخه منتشرشده درجا مجاز نیست؛ برای تغییر فایل/manifest نسخه جدید بسازید. کد خام لایسنس فقط هنگام صدور نمایش داده می‌شود؛ امن تحویل دهید. بایگانی حذف تاریخچه نیست.

## درخواست تغییر یا رفع اشکال

در همین گفتگو یا یک گفتگوی جدید آدرس `https://github.com/aliam664/App`، شاخه `arena/37af8e92-app` و این راهنما را معرفی کنید. بنویسید چه اتفاقی افتاده، چه انتظاری داشتید، نسخه/Request ID و مراحل تکرار. اسکرین‌شات بدون کد خصوصی کافی است. **کد مالک، pepper، کلید خصوصی یا service-role را در issue عمومی نفرستید.**

پیش از دست‌زدن به سرویس، عامل بعدی باید `docs/production-status.md`، `docs/deployment-fa.md` و وضعیت واقعی Supabase/GitHub را بخواند. داشتن این راهنما به معنی وجود دسترسی اتصال در گفتگوی جدید نیست؛ حساب همان مالک باید متصل باشد.

| تغییر | اقدام معمول |
| --- | --- |
| محتوا، لینک، مسیر، نقش و مجوز | فقط پنل |
| رابط/قابلیت/رفع باگ وب | کد + تست + انتشار خودکار سایت |
| منطق API | کد + تست + deploy مجدد تابع؛ push به‌تنهایی API را deploy نمی‌کند |
| دیتابیس | migration جدید + بکاپ + اجرای کنترل‌شده؛ migration قدیمی را ویرایش نکنید |
| موتور نصب/رفتار لانچر | ساخت و تحویل installer جدید؛ updater خودکار نداریم |
| عوض‌کردن کلید امضای سرور | برنامه‌ریزی مهاجرت اعتماد و احتمالاً installer جدید؛ کلید را بی‌برنامه عوض نکنید |

## نگهداری و هزینه

پروژه مستقل رایگان: **UHM Launcher**، شناسه `ewjvnqlqacljflvjbpbv`، منطقه us-east-1. TikTacProject دست‌نخورده است. [داشبورد پروژه](https://supabase.com/dashboard/project/ewjvnqlqacljflvjbpbv).

طبق [قیمت رسمی Supabase](https://supabase.com/pricing) هنگام راه‌اندازی: دو پروژه فعال رایگان، دیتابیس ۵۰۰ MB، فضای فایل ۱ GB، خروجی ۵ GB و cached egress برابر ۵ GB؛ توقف احتمالی پس از یک هفته بی‌استفاده‌بودن. فایل مودها روی آپلودرهای شما هستند و از این storage سرو نمی‌شوند. ترافیک API و تاریخچه رویدادها همچنان سهمیه مصرف می‌کند. این پلن نامحدود یا SLA نیست؛ هیچ سرویس پولی فعال نکرده‌ایم.

هفتگی Usage/Database size/Edge invocations و خطاهای تابع را در داشبورد بررسی کنید. جدول telemetry فعلاً حذف خودکار ندارد، چون تاریخچه کامل درخواست شده است. نزدیک سقف، ابتدا گزارش و بکاپ بگیرید و retention/rollup را آگاهانه تعیین کنید. محدودکننده فعلی Edge مشترک و برای پایلوت کوچک است (۱۲۰ درخواست API در دقیقه به‌طور مشترک، به‌جز health/preflight)؛ پیش از عرضه وسیع، limiter لبه قابل اعتماد، lookupهای indexمحور و آزمون بار لازم است.

`pg_cron` ساعتی چالش‌های منقضی و rate bucketهای قدیمی را پاک می‌کند؛ **بکاپ دیتابیس نیست**. بکاپ/restore خودکار خارج از سرویس در این راه‌اندازی پیکربندی نشده است. با CLI/ابزار مورد اعتماد، dump رمزگذاری‌شده منظم تهیه و restore را در مقصد آزمایشی مجاز امتحان کنید. مخزن GitHub فقط کد و migrationها را دارد، نه داده مشتری یا کلیدها. آرشیو recovery تحویلی نیز فقط کلیدها/اطلاعات اولیه است، نه بکاپ رویدادها و مشتریان آینده.

## بازیابی مالک یا دستگاه

آرشیو خصوصی recovery و رمز آن را دانلود کنید و در محل امن جدا از مخزن و ترجیحاً password manager/حافظه رمزگذاری‌شده نگه دارید. از بین رفتن محیط این گفتگو نباید تنها نسخه کلیدها را از بین ببرد. تغییر pepper باعث نامعتبرشدن lookup کدهای فعلی می‌شود.

یک مالک عملیاتی دومِ قابل اعتماد برای اضطرار ایجاد کنید. مالک نمی‌تواند دسترسی خودش را از پنل حذف یا دستگاه خودش را reset کند. اگر تنها مالک دستگاهش را از دست داد، مالک حساب Supabase پس از احراز هویت می‌تواند از SQL Editor پروژه صحیح، با ثبت audit و بررسی شناسه واقعی، `uhm.mutate_license(license_id,'reset',operator)` را اجرا کند. سپس همان کد روی دستگاه جدید فعال شود. برای recovery هرگز کلید service-role را داخل مرورگر برنامه قرار ندهید.

## محدودیت‌های صادقانه

CI ویندوز، audit وابستگی، آزمون‌های محلی و smoke واقعی API انجام شده‌اند؛ نصب این نسخه روی کامپیوتر شما با مود و آپلودر واقعی هنوز باید انجام شود. محصول ضدکرک مطلق نیست، آمار کلاینت اثبات ضدتقلب نیست، و توقف آنلاین لینک‌های قبلاً دریافت‌شده یا مجوزهای آفلاین را فوراً خنثی نمی‌کند. بات/سرور بازی خارجی هنوز معرفی و متصل نشده است.

# بازطراحی Owner و باگ‌یابی رابط کاربران — ۲۰۲۶/۱۱/۰۳

## نتیجه و محدوده

پنل مدیریت با حفظ لوگو، فونت‌های محلی و هویت آبی–فیروزه‌ای UHM بازطراحی شد. صفحه عمومی، رسانه‌های اصلی و کد مشترک سایت/دسکتاپ حفظ شدند؛ بازنویسی فناوری یا نسخه HTML جدا انجام نشد. تمرکز روی وضوح، آرامش بصری، عملکرد واقعی و دسترس‌پذیری بود، نه تزئین یا آمار ساختگی.

تست‌ها روی adapter محلی، داده و کلیدهای آزمایشی انجام شدند. **لایسنس مالک، binding دستگاه، اطلاعات تولید، کلید امضا، DB و Edge API تولید تغییر نکردند.** نصب‌کنندهٔ عمومی جدید در این مرحله منتشر نشده؛ تغییر وب با workflow معمول Pages منتشر می‌شود. preview پورت ۵۱۷۳ محیط آزمایشی است، نه production.

این گزارش، ادعای «هیچ باگی در هیچ دستگاهی وجود ندارد» یا گواهی رسمی WCAG نیست؛ محدودهٔ آزمون و محدودیت‌ها در ادامه مشخص‌اند.

## تغییرات طراحی Owner

- ناوبری راست‌به‌چپ در سه گروه «فضای کاری»، «مدیریت محتوا» و «نظارت و کنترل»؛ وضعیت انتخاب روشن و بدون چشمک‌زدن مجوزهای مخفی.
- نمایش نقش واقعی حساب از API در header و sidebar؛ کاربران دیگر به اشتباه Owner معرفی نمی‌شوند.
- نمای کلی با عنوان، زمان دریافت واقعی داده، آمار خوانا و میان‌برهای واقعی صدور لایسنس، ساخت پکیج، تیم و سرویس.
- بخش «در یک نگاه» برای draftها، اعتبارهای منقضی و خطاهای رسیدگی‌نشده؛ بدون درصد رشد، درآمد یا وضعیت امنیتی ساختگی.
- کارت‌ها، جدول‌ها، فیلترها، فضای خالی، border و تایپوگرافی یکپارچه؛ رنگ روشن و تاریک با کنتراست جداگانه.
- آمار فقط مطابق permission حساب رندر می‌شود. نبود مجوز خواندن لایسنس، به‌صورت «صفر لایسنس» نمایش داده نمی‌شود.
- فهرست رویدادها بر اساس زمان مرتب می‌شود و راه مستقیم به تاریخچه دارد.
- در موبایل یک منوی کامل استفاده می‌شود، نه bottom-nav ناقصی که بخش‌های مهم Owner را حذف کند.
- حالت فشرده همچنان فاصله‌ها را کم می‌کند و بعد از refresh باقی می‌ماند.

## ماتریس آزمون اجراشده

### آزمون خودکار طراحی

فرمان: `npm run test:design`.

- ۱۱ صفحه مدیریت: overview، licenses، packages، versions، devices، analytics، errors، team، service، logs، settings.
- ۶ صفحه کاربر: خانه، محتوا، تنظیمات کتابخانه، کتابخانه، دانلود و نصب، تنظیمات.
- هر ۱۷ صفحه در dark و light: **۳۴ اسکن axe** با tags مربوط به WCAG 2 A/AA و 2.1 AA، بدون violation گزارش‌شده در این حالت‌ها.
- هر حالت در عرض‌های **۳۲۰، ۳۹۰، ۶۴۰، ۷۰۰، ۷۰۱، ۹۰۰، ۱۲۸۰ و ۱۴۴۰**: مجموع **۲۷۲ کنترل عدم بیرون‌زدگی سند**. اسکرول داخلی جدول بزرگ، عمدی و مجاز است.
- چهار اسکن modal در حالت‌های مشخص: ساخت پکیج، صدور لایسنس، پرونده لایسنس و مجوزهای تیم؛ بدون violation در اجرای انجام‌شده.
- تست مستقل منوی موبایل/متن تبلت، refresh/history/deep-link، فرم ۳۲۰px و تغییرات ذخیره‌نشده، focus، کیبورد RTL، کاهش حرکت، retry، skip-link و حالت فشرده.

اسکن axe روی حالت‌های واقعاً رندرشده انجام شد؛ disabled rule یا exclude کلی برای سبزکردن نتیجه استفاده نشد. عدم گزارش axe، جای بازبینی انسانی یا تست واقعی screen reader را نمی‌گیرد.

### سایر تست‌ها

- **۱۹ تست مرورگر قبلی:** موفق؛ ورود، پکیج چندفایلی، تیم، خطاها، queue و رفتارهای قبلی حفظ شدند.
- **۴ تست build استاتیک Pages/branch:** موفق؛ حفظ assets/font، فعالیت بدون backend، refresh روی صفحه انتخاب‌شده و لینک لوگوی موبایل. انتظار قدیمیِ بازگشت به dashboard با قرارداد جدیدِ حفظ همان صفحه اصلاح شد، نه اینکه تست حذف شود.
- **۳ تست مرورگر دسترسی سفارشی:** موفق؛ دو expected-failure قبلی AUD-02/03 به regression عادی تبدیل شدند.
- **۱۰ سناریوی طراحی مرورگر:** موفق.
- **۱۸۱ تست عادی unit/API/DB + چهار expected-failure بازِ ممیزی سرور:** موفق در `npm run check`؛ ۱۹ تست route تازه نیز در همین عددند.
- typecheck، production build و format check موفق؛ npm audit صفر آسیب‌پذیری گزارش‌شده.

چهار expected-failure سرور هنوز بازند: limiter مشترک، بودجه تعداد گراف، بودجه مجموع فایل و range خاص IP. این بازطراحی رفع آن‌ها یا تأیید امنیت کامل نیست.

## محدودیت‌های دقیق

- اجرای محلی با Chromium و بررسی بصری screenshot انجام شد؛ Safari/iOS، Firefox، NVDA/VoiceOver، scaling خاص Windows و خود WebView2 روی PC کاربر آزمون دستی نشدند.
- صفحات کتابخانه/نصب در مرورگر، محدودیت Native را صریح نمایش می‌دهند. تست‌های قبلی native-bridge، IPC را شبیه‌سازی می‌کنند و اثبات نصب مود روی دیسک نیستند.
- تمام اندازه‌ها و ترکیب‌های محتوا در جهان قابل پوشش نیستند؛ هدف ماتریس regression قابل تکرار و رفع خطاهای مشاهده‌شده است، نه تضمین مطلق نبود باگ.

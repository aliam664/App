# راه‌اندازی امضای آپدیت لانچر

## وضعیت فعلی

- سیاست مورد تأیید کاربر: دانلود خودکار پس‌زمینه، بررسی امضا و نصب در خروج/اجرای بعدی در زمان امن، بدون تأیید جداگانه. عملیات فعال محتوا و بازی نباید قطع شوند.
- کاربر تولید کلید مستقل در محیط Agent و تحویل فایل خصوصی را تأیید کرد.
- جفت کلید تازه توسط `tauri signer generate` ساخته شد؛ کلید لایسنس تغییر نکرده و برای updater استفاده نشد.
- فقط کلید **عمومی** و نام Secret در `config/updater-public.json` ثبت شده‌اند. فایل کلید خصوصی و بسته بکاپ زیر `.local/` و خارج از Git هستند.
- خودآزمایی `tauri signer sign --app-version 0.1.0` روی یک فایل آزمایشی موفق شد و امضای version-bound تولید کرد. این خودآزمایی، تست آپدیت برنامه یا نصب واقعی نیست.
- updater هنوز به runtime و workflow انتشار متصل نشده است؛ این سند ادعای فعال‌بودن آپدیت آنلاین نیست.

## اقدام لازم مالک

1. فایل `UHM-updater-private-backup.zip` تحویل‌شده را **همین حالا دانلود و در محل امن بکاپ کنید**. فایل‌های خصوصی خارج از snapshot/Git هستند؛ به این محیط به‌عنوان بکاپ دائمی تکیه نکنید.
2. بسته و کلید داخل آن با گذرواژه رمز نشده‌اند؛ هر کس کلید را داشته باشد می‌تواند فایل آپدیت امضا کند. آن‌ها را در محل رمزگذاری‌شده/امن نگه دارید و در چت، release یا مخزن قرار ندهید.
3. به `https://github.com/aliam664/App/settings/secrets/actions` بروید و **New repository secret** را انتخاب کنید.
4. نام دقیق: `TAURI_SIGNING_PRIVATE_KEY`. مقدار: کل متن فایل `uhm-updater.key` داخل ZIP، نه فایل `.pub`.
5. اگر همین نام از قبل وجود داشت و منشأ آن روشن نیست، پیش از جایگزینی اطلاع دهید. تعویض کورکورانه کلید می‌تواند زنجیره اعتماد نصب‌های قبلی را قطع کند.
6. این کلید passphrase ندارد. `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` برای آن باید unset باشد؛ اگر Secret قبلی با این نام وجود دارد، ابتدا وضعیتش را اطلاع دهید.
7. فقط انجام‌شدن کار را تأیید کنید؛ مقدار Secret یا کلید خصوصی را در چت ارسال نکنید.

دسترسی فعلی Agent به لیست Secrets خطای ۴۰۳ مجوز داد. این خطا با درخواست پسورد/PAT یا ثبت اعتبارنامه کاربر در پروژه دور زده نمی‌شود. پس از تنظیم Secret، مرحله CI می‌تواند بدون چاپ مقدار، وجود و امکان امضای درست را بررسی کند.

## مرزهای امنیتی موردنیاز برای تکمیل

- امضا و نسخه هر artifact باید بررسی شوند؛ صرف HTTPS یا SHA به‌تنهایی جای اعتماد امضا را نمی‌گیرد.
- کلید خصوصی فقط در مرحله انتشار قابل‌اعتماد مصرف شود، نه build مربوط به PR غیرقابل‌اعتماد.
- تنظیم `requireSignedVersion` نسخه سازگار plugin بررسی شود تا manifest نتواند باینری قدیمی را با شماره نسخه تازه معرفی کند.
- هماهنگی اتمیک updater با jobهای فعال، بررسی اجرای بازی و محافظت از داده لایسنس/تنظیمات/رجیستری نصب لازم است.
- امضای Tauri با Authenticode ویندوز فرق دارد؛ این مرحله گواهی تجاری Windows تهیه نکرده است.
- plugin استاندارد الزاماً delta transfer ندارد. کاهش حجم artifact، تغییرات دیتابیس بدون rebuild و دانلود delta سه موضوع جدا هستند؛ ادعای پشتیبانی delta قبل از پیاده‌سازی/آزمون آن مجاز نیست.

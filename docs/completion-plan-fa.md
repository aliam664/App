# تکمیل عملیاتی لانچر — بررسی و برنامه اجرایی

## نتیجه بررسی سورس در ۲۰۲۶-۱۱-۰۲

- رابط Vite/TypeScript مشترک وب و Tauri/Rust؛ Electron قدیمی مرجع است و مقصد توسعه نیست.
- API فعلی TypeScript در Supabase Edge؛ PostgreSQL با schema خصوصی uhm، RLS و service-role فقط سمت سرور.
- لایسنس ES256، اتصال کلید دستگاه، سه سطح، مدیریت مجوزها و صف آفلاین موجودند و حفظ می‌شوند. هیچ کد یا کلید مالک در این سند نیست.
- موتور Native واقعاً HTTPS دانلود، SHA-256، ZIP/RAR/7z، استخراج محدود و backup/journal/rollback دارد؛ نمایشی معرفی‌کردن کل موتور نادرست است.
- کتابخانه فقط installed.json خود لانچر را نمایش می‌دهد؛ اسکن Cars/Tracks/Skins خارجی و کش حجم ندارد.
- انتخاب مسیر دستی است؛ کشف Steam/کتابخانه‌ها/Documents/Content Manager وجود ندارد.
- دانلود pause/resume/cancel، mirror failover و سرعت/ETA ندارد. نصب پس از استخراج بدون پیش‌نمایش تأیید کاربر اعمال می‌شود.
- پکیج فایل/مرحله/وابستگی دارد، اما metadata محتوا، source-subdirectory، mirror، زمان انتشار، کانال تست و نسخه‌سازی پیشرفته ناقص‌اند. children فقط JSON هستند.
- سایت واقعی با Native تفاوت دسترسی دارد: مرورگر نمی‌تواند فایل‌های بازی را اسکن/نصب کند؛ برای آن داده جعلی اضافه نمی‌شود.

## مراحل اجرایی

1. قراردادهای سازگار با نسخه قبلی، metadata، mirror، dependency مرحله، زیرپوشه آرشیو و migration نرمال‌سازی؛ تست SQL/API.
2. کشف مسیرهای Steam و نصب‌های متعدد؛ تنظیمات ماندگار، مسیرهای Documents/CM؛ انتخاب معتبر و async.
3. اسکن واقعی کتابخانه، کش اندازه/metadata، تصاویر امن، provenance، جست‌وجو/فیلتر و حذف قابل‌بازیابی با پیش‌نمایش و کنترل تغییر فایل.
4. کنترل دانلود، ادامه HTTP Range با اعتبارسنجی و hash نهایی، retry/mirror، سرعت/ETA، جلوگیری از کار تکراری؛ پیش‌نمایش بعد از staging و قبل از تغییر بازی.
5. تکمیل Builder/کاتالوگ با امکانات Backend مرحله اول و اتصال صفحات مستقل کتابخانه/محتوا/تنظیمات.
6. build/typecheck/آزمون‌های واحد، SQL و مرورگر؛ آزمون واقعی Rust روی Windows CI. انتشار فقط پس از نتیجه آزمون؛ migration/API جدید بدون تأیید وضعیت واقعی مقصد، «مستقر» محسوب نمی‌شوند.

## مرزهای ایمنی

عملیات سفارشی به معنی shell یا اجرای EXE نیست. مقصدها باید نسبی و داخل root معتبر باشند. حذف محتوا به قرنطینه منتقل می‌شود و overwrite هنگام restore ممنوع است. نصب/حذف از یک قفل استفاده می‌کنند. متادیتای ناموجود حدس زده نمی‌شود. بکاپ مالک/کلیدها و لایسنس فعال کاربر تغییر نمی‌کنند.

این فایل برنامه است، نه ادعای تکمیل همه مراحل. گزارش نهایی باید آزمون‌شده/پیاده‌شده/مستقر/باقی‌مانده را تفکیک کند.

# بررسی نسخه منتشرشده 1.0.0 و مسیر استفاده مجدد

## مرجع قطعی

- Release: `v1.0.0`، UHM Pack Installer 1.0.0، منتشرشده ۲۰۲۶-۰۹-۱۳.
- commit پشت annotated tag: `12538c48be54e95dfe52bca9e0f04ecb38826213`.
- فناوری واقعی: **Tauri 2 / Rust**. وجود فایل‌های Electron در تاریخچه پروژه دلیل Electron بودن این انتشار نیست؛ توضیح قبلی در این مورد اصلاح شد.
- سورس با `git show` بررسی شد؛ branch تغییر نکرد و EXE قدیمی اجرا نشد. ادعای «تمام تست‌های قدیمی اجرا شدند» نداریم.

## بخش‌های بررسی‌شده

| ماژول قدیمی | قابلیت | نتیجه استفاده مجدد |
|---|---|---|
| `installer.rs` | backup اولین نسخه اصلی، نگاشت فایل نصب‌شده، exclude و uninstall | الگوی حفظ اولین original و برگرداندن آن در uninstall ارزش استفاده دارد؛ باید روی journal/مالکیت/قفل و root معتبر فعلی تطبیق داده شود. هنوز uninstall جدید از آن ساخته نشده است. |
| `mod_installer.rs` | درخت مجازی آرشیو، تشخیص Car/Track/Skin/App/PP و طرح چندمحتوایی | مرجع اصلی برای تکمیل importer؛ تشخیص از اجرای فایل جدا خواهد ماند. هنوز کل ماژول منتقل نشده است. |
| `library.rs` | فهرست تصاویر، اسکین/لی‌اوت، آمار و trash | ترتیب و نام‌های واقعی تصاویر اکنون در `content_rules.rs` بازاستفاده و به scanner فعلی متصل شدند. |
| `archive.rs` | ZIP و RAR و خطاهای رمز | taxonomy خطاها قابل استفاده است؛ استخراج‌کننده جدید ZIP/RAR/7z و محدودیت‌های فعلی حفظ می‌شوند. وابستگی قدیمی ZIP 2 بدون بررسی audit برنمی‌گردد. |
| `lib.rs` | مسیر Steam، command bridge، worker و install cancel | الگوها بررسی شدند؛ مسیر‌یاب فعلی نصب‌های متعدد و قفل‌های جدید را هم دارد و با نسخه قدیمی جایگزین کلی نمی‌شود. |
| تنظیمات build | LTO/size optimization و NSIS LZMA، installer قدیمی حدود ۳٫۷ MB | برای کاهش اندازه نسخه نهایی بررسی خواهد شد؛ به معنی داشتن delta updater در نسخه قدیمی نیست. |

## مواردی که نباید بدون تطبیق کپی شوند

1. `uninstall_files` قدیمی `dest` و `backupPath` را از ورودی می‌گیرد و پیش از copy/delete به root معتبر bind نمی‌کند؛ `stopAt` مرز prune است، نه مجوز حذف فایل. در جریان معمول UI ممکن است ورودی درست باشد، ولی برای مرز امنیتی Native جدید کافی نیست. فرمان حذف باید فقط از registry/journal مورداعتماد و مسیرهای بررسی‌شده ساخته شود.
2. restore قدیمی در صورت تداخل، پوشه فعلی را با suffix پشتیبان می‌گیرد و نسخه trash را جایگزین می‌کند. نسخه فعلی در تداخل متوقف می‌شود. انتخاب رفتار نهایی و رضایت کاربر قبل از تغییر لازم است.
3. trash قدیمی اول copy/delete و بعد ثبت metadata انجام می‌دهد. برای مقاومت در برابر crash باید intent پیش از جابه‌جایی ثبت شود؛ journal جدید حذف نمی‌شود.
4. تشخیص Kunos/DLC با prefix اسم پوشه، اثبات منشأ محتوا نیست. طبق درخواست کاربر داده حدسی نباید به‌عنوان حقیقت نمایش داده شود.
5. لی‌اوت قدیمی فقط `layout_<number>` را قبول می‌کرد؛ scanner جدید نام‌های واقعی دیگر مثل `sprint` را هم می‌بیند و این پیشرفت نباید از دست برود.
6. خواندن metadata/تصویر از آرشیو قدیمی در برخی مسیرها `read_to_end` بدون سقف روشن دارد؛ محدودیت حجم، path traversal، reparse، archive bomb و hash فعلی حفظ می‌شوند.

## تغییر انجام‌شده در این بررسی

قواعد pure تصاویر با ذکر commit مرجع به `src-tauri/src/content_rules.rs` منتقل شدند. scanner اکنون تصاویر مستقیم `ui/preview*`، فرمت JPEG و گزینه‌های light/alternate نسخه قدیمی را پیش از fallback اسکین و badge بررسی می‌کند؛ Track/Layout/Skin نیز از همان قواعد استفاده می‌کنند. دسترسی فایل همچنان از `safe_target` و بررسی magic bytes/سقف تصویر می‌گذرد. نام/منشأ محتوای مفقود حدس زده نمی‌شود.

دو تست Rust اضافه شده‌اند: ثبات ترتیب/نام‌های legacy و اتصال واقعی scanner به fixture فایل‌سیستم، همراه با رد تصویر خراب. `npm run check` با ۱۱۰ تست موفق شد. CI مربوط به commit `bcb5d52842f07d60d848e790185330f51b9c947d` در run [41510980533](https://github.com/aliam664/App/actions/runs/41510980533) برای هر دو job وب/API و Windows Native موفق شد؛ مرحله Native شامل اجرای تست‌ها، audit و ساخت installer است. GUI واقعی روی سیستم کاربر هنوز تست نشده است.

## تصمیم‌های باز برای مرحله انتشار

کاربر اعلام کرده انتشار جدید هنوز به کاربران داده نشده است؛ نیاز به مهاجرت خودکار جمعیت نصب‌شده عمومی فرض نمی‌شود. با این وجود نصب آزمایشی 0.1.0 updater ندارد و یک بار باید نسخه مجهز به updater را دریافت کند.

پیش از پیاده‌سازی رفتار نصب/ری‌استارت خودکار، سیاست آن باید مستقیماً از کاربر پرسیده شود. همچنین «آپدیت کم‌حجم» باید از سه حالت جدا شود: تغییر کاتالوگ/پکیج از سرور، آپدیت امضاشده خود برنامه و delta باینری. نسخه قدیمی updater یا delta آماده‌ای ندارد که صرفاً کپی شود.

## تصمیم تأییدشده آپدیت

کاربر گزینه «دانلود و نصب خودکار در زمان امن» را تأیید کرد: دریافت پس‌زمینه، بررسی امضا، نصب بدون تأیید جداگانه هنگام خروج یا اجرای بعدی پس از پایان عملیات فعال. نباید بازی یا نصب/دانلود فعال ناگهان قطع شود.

مخزن GitHub عمومی است؛ release asset عمومی برای updater به توکن تعبیه‌شده در برنامه نیاز ندارد. بررسی رسمی `plugins/updater/README.md` در `tauri-apps/plugins-workspace` استفاده از plugin امضاشده Tauri را تأیید می‌کند، ولی plugin به‌تنهایی وعده delta کم‌حجم یا مهاجرت نسخه فاقد updater نیست.

در زمان بررسی اولیه کلیدی تولید نشده بود؛ سپس کاربر تولید و تحویل فایل را تأیید کرد. کلید مستقل ساخته و فقط کلید عمومی در Git ثبت شد؛ راه‌اندازی Secret و اتصال runtime هنوز باقی است. [وضعیت و راهنمای تحویل](updater-setup-fa.md). `gh secret list` با ۴۰۳ `Resource not accessible by integration` پاسخ داد؛ این محدودیت دسترسی Secrets است، نه دلیل درخواست رمز یا توکن GitHub از کاربر. انتخاب محل تولید و نگهداری کلید باید از کاربر تأیید شود. کلید لایسنس برای updater استفاده نخواهد شد.

## پروژه چیست و چگونه کار می‌کند؟

UHM برای ارائه و مدیریت محتوای مرتبط با **Assetto Corsa** طراحی شده است. مدیر، بسته‌ها و مجوزها را در پنل تعریف می‌کند؛ کاربر با لایسنس فعال کاتالوگ را می‌بیند و در نسخه دسکتاپ می‌تواند عملیات Native پشتیبانی‌شده را انجام دهد. سه سطح اشتراک `Normal`، `Pro` و `VIP` و نقش‌های مستقل مدیریتی وجود دارند.

```text
  مرورگر / سایت ───────┐
                        ├── رابط مشترک TypeScript / Vite
  لانچر Windows / Tauri ┘          │
             │                     ▼
             │              API / Supabase Edge
             │                     │
             │              PostgreSQL + RLS
             ▼
  موتور Rust: بررسی طرح، دانلود، هش، staging و نصب روی مسیر مجاز بازی
             │
             └── فایل بسته از میزبان HTTPS مستقل مدیر دریافت می‌شود
```

- **وب:** رابط، کاتالوگ و پنل را ارائه می‌دهد؛ مرورگر به فایل‌های بازی دسترسی Native ندارد و نصب واقعی را شبیه‌سازی نمی‌کند.
- **دسکتاپ:** همان رابط را داخل Tauri اجرا می‌کند و فرمان‌های Native برای شناسایی بازی، دانلود، نصب و کتابخانه در اختیار دارد.
- **API:** اعتبار لایسنس، اثبات دستگاه، سطح دسترسی، بسته‌ها و عملیات مدیر را سمت سرور بررسی می‌کند. رابط به‌تنهایی مرز امنیتی نیست.
- **میزبانی فایل:** فایل مودها در بسته برنامه یا پایگاه داده قرار نگرفته‌اند؛ مدیر باید فایل معتبر را جداگانه میزبانی و لینک مستقیم، اندازه و هش آن را ثبت کند.

## آیا پروژه کامل است؟

**پاسخ کوتاه: خیر، محصولی با قابلیت‌های قابل توجه و انتشار آزمایشی است، نه محصول نهایی اثبات‌شده در همه شرایط.** جدول زیر بین وجود قابلیت، آزمایش و آمادگی عملیاتی تفاوت می‌گذارد.

| --- | --- | --- |

| لایسنس و دستگاه | فعال‌سازی، سطح اشتراک، اثبات کلید دستگاه، تمدید و مدیریت | کلید مرورگر و Windows مستقل‌اند؛ کنترل کامل دستگاه یا جلوگیری از بازنشر فایل دانلودشده تضمین نمی‌شود. |

**موانع مهم قبل از عرضه گسترده:** آزمایش تعاملی روی Windows با بازی و بسته‌های واقعی و نسخه پشتیبان مستقل؛ بررسی امنیتی و بار مستقل؛ تصمیم‌گیری و آزمون سیاست بازگردانی فایل‌های شخصی؛ برنامه بکاپ/restore، پایش، محدودسازی ترافیک و ظرفیت؛ تعیین وضعیت گواهی ناشر ویندوز و فرآیند پشتیبانی. هیچ‌یک از تست‌های موجود، تضمین «ضدکرک مطلق» یا نصب موفق روی تمامی دستگاه‌ها نیست. گزارش‌های تاریخی ممکن است وضعیت checkpoint قدیمی را توصیف کنند؛ برای 0.1.2 ابتدا [گزارش انتشار](docs/release-0.1.2-fa.md) را بخوانید.

## راهنمای کاربر

### نصب و راه‌اندازی

1. روی **Windows 10/11 نسخه ۶۴بیتی**، [نصاب 0.1.2](https://github.com/aliam664/App/releases/download/uhm-launcher-v0.1.2/UHM-Launcher-0.1.2-x64-setup.exe) را از انتشار رسمی دریافت و هش را بررسی کنید. برای برنامه دسکتاپ WebView2 لازم است؛ اگر روی سیستم وجود ندارد، آن را از منبع رسمی Microsoft نصب کنید.
2. پیش از تغییر محتوای بازی، از پوشه و تنظیمات مهم خود **نسخه پشتیبان مستقل** بگیرید. بسته‌های آزمایشی را ابتدا فقط روی مسیر جداگانه آزمایش کنید.
3. نصاب را اجرا و لانچر را باز کنید. برای استفاده از قابلیت‌های متصل، اینترنت و لایسنس معتبر لازم است.
4. کد لایسنس را در بخش فعال‌سازی وارد کنید. اتصال دستگاه بر اساس کلید دستگاه است؛ فعال‌سازی در مرورگر و برنامه Windows می‌تواند دو هویت متفاوت ایجاد کند. اگر می‌خواهید لایسنس اصلی را در دسکتاپ استفاده کنید، آن را ابتدا در مرورگر آزمایش نکنید.
5. مسیر نصب بازی را انتخاب و اعتبارسنجی کنید؛ سپس در کاتالوگ بسته‌های مجاز را بررسی کنید. اگر بسته‌ای نیست، ممکن است هنوز محتوای عمومی منتشر نشده باشد.
6. پیش از تأیید نصب، مقصدها، پیش‌نیازها و تداخل‌ها را بخوانید. خطا، نبود فضای کافی یا لغو پیش‌نمایش را موفقیت نصب فرض نکنید. بسته‌ها و رفتارشان به فایل‌ها و تنظیمات واقعی مدیر وابسته‌اند.

### به‌روزرسانی و تعویض دستگاه

نسخه‌های سازگار با updater امضاشده، آپدیت را بررسی و در زمان امن، هنگام خروج یا اجرای بعدی، اعمال می‌کنند؛ تنظیم بررسی خودکار و بررسی دستی در نسخه جدید وجود دارد. نسخه‌های قدیمی بدون updater به دریافت دستی نصاب نیاز دارند. برای تعویض دستگاه، با مدیر درباره آزادسازی مجاز دستگاه تماس بگیرید؛ کد یا کلید دستگاه را عمومی نکنید. دسترسی آفلاین محدود است و لغو آنلاین لزوماً فوراً به دستگاهی که قطع است نمی‌رسد.

## راهنمای مدیر

1. با لایسنس مدیریتی مجاز وارد پنل شوید. نقش مدیریت از سطح VIP به‌تنهایی نتیجه نمی‌شود. برای همکاران، لایسنس جدا و حداقل مجوز لازم صادر کنید.
2. یک دسته و بسته بسازید؛ نام، سطح، توضیح، نسخه و پیش‌نیازها را مشخص کنید. فایل واقعی را در میزبان HTTPS قابل اتکا قرار دهید.
3. لینک مستقیم، SHA-256، اندازه دقیق بایت، نوع فایل، mirrorهای اختیاری و مراحل copy/extract را وارد کنید. محاسبه هش در رابط، فایل را آپلود نمی‌کند؛ EXE بسته خودکار اجرا نمی‌شود.
4. مقصدها باید نسبی و در محدوده مجاز بازی باشند. پیش‌نویس ذخیره‌شده را بررسی و در محیط جداگانه تست کنید؛ preview را بخوانید و سپس با مجوز لازم منتشر کنید.
5. انتشار دارای snapshot نسخه است؛ برای تغییر محتوای منتشرشده نسخه جدید بسازید. بازگرداندن snapshot در سرور، لزوماً فایل‌های نصب‌شده کاربران را بازنویسی نمی‌کند.
6. رویدادها، خطاها، ظرفیت و پشتیبان‌ها را پایش کنید. کد لایسنس، رمز آرشیو، توکن، کلید خصوصی و URLهای حساس را در issue عمومی ثبت نکنید.

## اجرای محلی و توسعه

### پیش‌نیازها

- Git و **Node.js 22.12 یا جدیدتر** همراه npm؛ نصب وابستگی به اینترنت نیاز دارد.
- برای اجرای/ساخت دسکتاپ: Rust stable، ابزار ساخت C++ ویندوز و WebView2؛ دستورالعمل‌ها و پیش‌نیازهای [Tauri](https://v2.tauri.app/start/prerequisites/) را نیز ببینید.
- این دستورات برای توسعه‌دهندگان‌اند؛ کاربران معمولی فقط نصاب رسمی را نیاز دارند.

```bash
git clone https://github.com/aliam664/App.git
cd App
npm ci
npm run dev
```

آدرس توسعه معمولاً `http://localhost:5173` است. `npm run dev` سرور محلی API و Vite را برای **sandbox** بالا می‌آورد؛ داده‌های آزمایشی در `.local/` نگهداری می‌شوند و کدهای آزمایشی در سرویس واقعی معتبر نیستند. حالت توسعه مجوز نمایشی Owner دارد: **آن را در شبکه عمومی یا محیط عملیاتی مستقر نکنید.** استفاده از `localhost` در این راهنما یعنی همان کامپیوتری که سرور توسعه را اجرا می‌کند.

`.env.example` فقط نمونه متغیرهای عمومی مرورگر است. `VITE_API_BASE`، `VITE_SUPABASE_URL` و `VITE_SUPABASE_PUBLISHABLE_KEY` ممکن است در build متصل استفاده شوند. هر چیزی با پیشوند `VITE_` به مرورگر می‌رسد؛ service-role، pepper، توکن، رمز یا کلید خصوصی را در آن یا Git قرار ندهید. برای ایجاد/استقرار مستقل، ابتدا [راهنمای استقرار](docs/deployment-fa.md) و تنظیمات عمومی نمونه را بخوانید؛ صرف push کردن API یا migration را deploy نمی‌کند.

| دستور | کاربرد |
| --- | --- |
| `npm run typecheck` | بررسی TypeScript بدون خروجی |
| `npm test` | تست‌های Vitest، از جمله تست‌های API و دیتابیس ایزوله |
| `npm run check` | typecheck، تست‌ها و build |
| `npm run build` | build معمولی در `dist/` |
| `npm run test:e2e` | تست مرورگر Playwright، پس از نصب مرورگر |
| `npm run test:design` | بررسی‌های رابط و دسترس‌پذیری |
| `npm run build:pages` / `npm run build:branch` | buildهای نمایشی sandbox |
| `npm run build:live-pages` / `npm run build:live-branch` | build متصل Pages / fallback شاخه |
| `npm run build:edge` | تولید artifact مربوط به Edge، نه استقرار خودکار آن |

برای مرورگر تست در محیط مناسب: `npx playwright install --with-deps chromium`. داده و محیط واقعی را با sandbox اشتباه نگیرید.

## ساخت نسخه ویندوز

در Windows و PowerShell، پس از نصب پیش‌نیازها:

```powershell
npm ci
# dot-source لازم است تا متغیرهای هش extractor در همین session بمانند.
. ./scripts/prepare-extractor.ps1
npm run desktop:dev
# برای build، ابتدا تنظیمات عمومی و trust root مناسب را آماده کنید:
npm run desktop:build
```

استخراج ZIP در Rust انجام می‌شود. برای RAR/7z اسکریپت، ابزار رسمی نسخه‌ثابت 7-Zip را با بررسی هش آماده می‌کند؛ بدون ابزار و هش معتبر این فرمت‌ها fail-closed هستند. فایل‌های تولیدی extractor در Git نیستند و مجوزهایشان باید همراه بسته بماند. build عملیاتی به `UHM_LICENSE_PUBLIC_JWK`، `UHM_LICENSE_ISSUER` و `UHM_LICENSE_KEY_ID` هماهنگ با سرور نیاز دارد؛ **کلید خصوصی را وارد build نکنید**. بسته محلی، به خودی خود همان binary امضاشده release نیست. توضیحات بیشتر: [extractor](src-tauri/resources/extractor/README.md)، [استقرار](docs/deployment-fa.md)، [updater](docs/updater-setup-fa.md).

## تست، امنیت و عملیات

### شواهد آزمون

- در بررسی محلی این شاخه در ۲۰۲۶/۱۱/۰۸: `npm ci` و `npm run check` موفق؛ **۲۲۲ تست**، typecheck و build موفق. npm audit در نصب، آسیب‌پذیری گزارش نکرد. Build هشدار اندازه chunk و چند هشدار annotation وابستگی داشت.
- این بررسی محلی روی Linux، آزمون تعاملی Windows، بازی واقعی، Rust Native یا سرویس تولید نبود.
- گزارش انتشار، [Platform checks](https://github.com/aliam664/App/actions/runs/41804408252)، [انتشار و بررسی امضا](https://github.com/aliam664/App/actions/runs/41805407297) و [ارتقای خودکار Windows](https://github.com/aliam664/App/actions/runs/41805527112) را برای commit انتشار مستند کرده است. سناریوها شامل fixture و runner ایزوله‌اند؛ با آزمون روی PC مشتری برابر نیستند.

### مرزهای امنیت و نگهداری

لایسنس و طرح نصب امضاشده، مجوزهای سمت سرور، RLS، بررسی هش و محدودیت مسیرها بخشی از طراحی‌اند؛ اما هیچ سیستمی ضدکرک مطلق نیست. DPAPI هویت نرم‌افزاری را محافظت می‌کند، نه تأیید سخت‌افزاری غیرقابل کلون. فایل مجاز دانلودشده لزوماً از بازنشر محافظت نمی‌شود. در استقرار عمومی باید ورودی قابل اعتماد، rate limiting، امنیت میزبان فایل، ظرفیت، مانیتورینگ و backup/restore مستقل بررسی شوند. گزارش [ممیزی امنیت](docs/security-audit-2026-11-03-fa.md) تاریخی است؛ اصلاح بعضی یافته‌ها در مراحل بعدی به معنی بسته‌شدن تمام ریسک‌ها نیست.

### سایت و انتشار

طبق تنظیم GitHub Pages مشاهده‌شده در ۲۰۲۶/۱۱/۰۸، سایت از ریشه شاخه `arena/37af8e92-app` با روش legacy سرو می‌شود، **نه از main**. بنابراین ادغام این سورس در `main` به‌تنهایی تغییر سایت زنده را تضمین نمی‌کند. workflow سایت برای `main` هم build می‌سازد، اما deploy در حالت Actions فقط وقتی انجام می‌شود که Pages به workflow تنظیم شده باشد؛ در حالت فعلی منبع legacy تعیین‌کننده است. تغییر تنظیم Pages، استقرار API و migrationها عملیات مستقل‌اند. [جزئیات Pages](docs/github-pages-fa.md).

لانچر مستقل Assetto Corsa، پنل مدیریت فارسی، API لایسنس و هسته نصب Native.

> **وضعیت: پایلوت 0.1.0 متصل به سرویس واقعی.** پروژه مستقل رایگان Supabase، دیتابیس، Edge API و مالک لایسنس‌محور راه‌اندازی شده‌اند. سایت به API واقعی متصل است. نصب‌کننده Windows بدون امضای دیجیتال است؛ آزمون عملی با بازی و مود واقعی و gateهای عرضه تجاری همچنان لازم‌اند. هیچ secret واقعی در سورس نیست.

## سایت زنده با همان کد برنامه

`index.html` ریشه، ورودی واحد برنامه و سایت است؛ نسخه HTML/طراحی جداگانه نگهداری نمی‌شود. با `npm run build:live-pages` خروجی استاتیک متصل برای `/App/` ساخته می‌شود و workflow انتشار با هر push روی همین شاخه یا `main` اجرا می‌شود.

سایت **https://aliam664.github.io/App/** اکنون با تنظیم legacy موجود و fallback کامپایل‌شده کار می‌کند؛ تغییر دستی تنظیم Pages برای استفاده لازم نیست. workflow ابتدا sandbox را تست و سپس build متصل را منتشر می‌کند. `/Uhm/` دست‌نخورده است.

## اجرای سریع

نیازمندی: Node.js 22.12 یا بالاتر.

```sh
npm ci
npm run dev
```

`http://localhost:5173` — لانچر؛ دکمه «پنل مدیریت» برای ورود نمایشی.

- حالت توسعه با نوار مشخص نمایش داده می‌شود.
- تولید کد، فعال‌سازی با امضای P-256، تغییر وضعیت لایسنس و ذخیره پیش‌نویس واقعی‌اند، اما روی داده محلی.
- حالت نمایشی اجازه دسترسی مالک به هر بازدیدکننده پیش‌نمایش می‌دهد؛ **آن را روی سرور عملیاتی deploy نکنید.**
- داده و کلیدهای آزمایشی در `.local/` و خارج Git هستند.
- مرورگر هیچ فایل بازی را نصب نمی‌کند؛ progress یا موفقیت نصب جعلی تولید نمی‌شود.
- `NODE_ENV=production` اجرای سرور نمایشی را متوقف می‌کند.

## ساختار

| مسیر | مسئولیت |
|---|---|
| `index.html` | ورودی مشترک سایت و برنامه |
| `apps/web/` | رابط لانچر و پنل، فارسی/RTL و responsive |
| `packages/contracts/` | schema، مسیر امن، tier و dependency planner |
| `backend/src/` | API مشترک، امضا، authorization و repository عملیاتی |
| `backend/dev/` | سرور و ذخیره محلیِ مخصوص توسعه |
| `supabase/` | migration، RPC اتمیک و Edge Function |
| `src-tauri/` | Rust، هویت DPAPI، دانلود، استخراج، نصب/بازیابی |
| `tests/` | تست قرارداد، API، PostgreSQL و مرورگر |
| `docs/` | معماری، امنیت، ریسک و راه‌اندازی |

کد قدیمی Electron در `main.js`، `preload.js` و `src/` برای مرجع حفظ شده و در برنامه جدید بارگذاری یا بسته‌بندی نمی‌شود. IPC قدیمی برای انتشار جدید تأیید نشده است.

## قابلیت‌های فعلی

- کاتالوگ، فیلتر دسته/اشتراک، جست‌وجو، جزئیات و وابستگی‌ها.
- فعال‌سازی و تمدید آنلاین بدون حساب ایمیل برای کاربر؛ challenge یک‌بارمصرف و کلید دستگاه.
- مجوز ES256 با محدودیت ۳+۷ روز و سقف پایان اشتراک؛ کنترل سطح در API.
- تولید تکی/گروهی لایسنس، نمایش یک‌باره کد و CSV، تعلیق/لغو/تمدید/reset دستگاه.
- نقش‌های Owner/License/Content/Support/Viewer؛ بررسی server-side و MFA برای تغییرات.
- پنل پکیج: چند فایل، SHA-256، مقصد نسبی، کپی/استخراج، ترتیب فایل‌ها و dependency.
- draft/publish/archive، ذخیره snapshot انتشار در PostgreSQL و تغییرناپذیری نسخه منتشرشده.
- API طرح نصب امضاشده، گزارش کلاینت، رویدادهای مدیریتی و آمار برگرفته از داده واقعی.
- Rust: انتخاب/اعتبارسنجی مسیر، دانلود stream و هش، کنترل URL/redirect/DNS، ZIP، آداپتور RAR/7z با ابزار pinشده، staging، backup، journal و crash recovery.
- Windows CI برای تست Native و ساخت installer آزمایشی unsigned.

تست دیتابیس migration واقعی را در PostgreSQL مبتنی بر PGlite اجرا می‌کند؛ جای آزمون یکپارچه روی پروژه واقعی Supabase را نمی‌گیرد.

## نسخه ویندوز

Rust stable، Windows Build Tools و WebView2 لازم‌اند.

```powershell
npm ci
# این اسکریپت را با dot-source اجرا کنید تا متغیرهای hash در همان PowerShell بمانند.
. ./scripts/prepare-extractor.ps1
npm run desktop:dev
# پس از تنظیم public configuration و trust root:
npm run desktop:build
```

در build عملیاتی باید `UHM_LICENSE_PUBLIC_JWK`، `UHM_LICENSE_ISSUER` و `UHM_LICENSE_KEY_ID` با کلید عمومی سرور هماهنگ باشند. هیچ کلید خصوصی به build لانچر ندهید. بدون trust root معتبر نصب fail-closed است.

ابزار رسمی 7-Zip با نسخه و checksum ثابت دریافت، بدون اجرای installer استخراج و در زمان اجرا دوباره hash می‌شود. نبودن ابزار/هش معتبر باعث رد RAR/7z می‌شود. مجوزهای همراه ابزار باید در بسته بمانند.

## محدودیت‌های باقیمانده

این نسخه کل سند اولیه را «کامل و آماده تولید» اعلام نمی‌کند. موارد مهم پیش از فروش:

- آزمون عملی Windows با بازی/آرشیو واقعی، تست نفوذ، load test و audit بیشتر extractor.
- limiter ورودی مورد اعتماد برای مقیاس بزرگ، retention، مانیتورینگ ظرفیت و بکاپ/restore خودکار؛ سرویس واقعی و smoke اولیه انجام شده‌اند.
- مسیر اختیاری Auth+MFA برای بازیابی اضطراری نیازمند ثبت عامل واقعی است؛ روش عادی دسترسی مدیر، لایسنس و proof دستگاه است و راه‌اندازی شده است.
- صفحه‌بندی تاریخچه بیشتر از ۵۰۰ انتشار اخیر و rollback کاربرمحور فایل‌ها؛ تاریخچه اخیر، جزئیات و پیش‌نویس از snapshot پیاده شده است.
- پشتیبانی از dependency version ranges، حذف فایل منسوخ و diff update؛ فعلاً طرح امضاشده نسخه‌های جاری را pin می‌کند و فایل منسوخ خودکار حذف نمی‌شود.
- updater امضاشده به Native متصل و کلید آن بدون تنظیم دستی مالک، سمت سرور نگهداری شده است؛ وضعیت آزمون/انتشار در [گزارش updater](docs/updater-setup-fa.md). امضای Authenticode ویندوز هنوز تهیه نشده است.
- بررسی حقوق محتوا، دسترسی شبکه هدف و تداوم/هزینه سرویس.

توقف/ادامه/لغو دانلود و قرنطینه/بازیابی انتخابی فایل‌ها پیاده شده‌اند. uninstall کامل و وابستگی‌محور پکیج هنوز تکمیل نشده است. نصب dependencyها تراکنش مستقل دارد؛ شکست پکیج اصلی، dependency موفق قبلی را حذف نمی‌کند.


### تاریخچه مراحل پیشین (اعداد زیر تاریخی‌اند؛ وضعیت فعلی در گزارش‌هاست)
- تاریخچه واقعی انتشار از snapshotهای تغییرناپذیر، مشاهده changelog و ساخت پیش‌نویس از انتشار قبلی در پنل مدیریت پیاده شده است.
- پیش‌نویس نسخه جدید، انتشار فعلی را از کاتالوگ حذف نمی‌کند. migration دوم با lookup ایندکس‌شده، مستقل از محدودیت صفحه تاریخچه کار می‌کند.
- بازگردانی خودکار فایل‌های نصب‌شده به یک انتشار قدیمی هنوز پیاده نشده؛ این با بازیابی تراکنش ناقص که در موتور نصب وجود دارد متفاوت است.
- `npm run format:check` بررسی فرمت کد را اجرا می‌کند؛ `npm run format` آن را اصلاح می‌کند.
- بسته JS اصلی پس از حذف واردسازی همه آیکن‌ها حدود ۱۷۲ کیلوبایت (۵۲ کیلوبایت gzip) است؛ فونت‌ها محلی‌اند.

- مجوز پس از سه روز، هنگام بازشدن برنامه و سپس بررسی ساعتی، آنلاین تازه‌سازی می‌شود؛ قطعی شبکه مجوز آفلاین معتبر را حذف نمی‌کند. تمدید شناسه دقیق لایسنس را با proof همان دستگاه تطبیق می‌دهد.
- بررسی محلی نهایی: ۷۸ تست قرارداد/API/PostgreSQL و ۵ تست مرورگر. نتایج Native مستقل در GitHub Actions ثبت می‌شوند.

- موتور فعلی سقف محافظه‌کارانه ۲۰ گیگابایت برای مجموع دانلود هر پکیج/خروجی بازشده، ۲۰هزار entry و نسبت بازشدن ۲۰۰ دارد؛ پکیج بزرگ‌تر باید با سیاست روشن به چند پکیج تقسیم شود یا این سقف‌ها پس از آزمون تغییر کنند.


### نتیجه ساخت Windows در CI
اجرای [41340337412](https://github.com/aliam664/App/actions/runs/41340337412) در Windows موفق شد: ۱۵ تست Native (شامل DPAPI/امضای P-256، ZIP/RAR/7z واقعی و حالت‌های قطع تراکنش)، `cargo audit` بدون vulnerability مسدودکننده و تولید NSIS آزمایشی unsigned. هشدارهای وابستگی غیرمستقیم `proc-macro-error` و `glib` در audit باقی هستند؛ دومی مربوط به مسیر GTK/Linux است و build هدف این نسخه Windows است. موفقیت CI معادل تست روی نصب واقعی Assetto Corsa یا تأیید امنیت کامل نیست.

وابستگی‌ها از artifact اجرای موفق Windows pin می‌شوند. پس از افزودن وابستگی updater و دریافت lock جدید، اجرای نهایی مجدداً با `cargo test --locked` بررسی می‌شود.
